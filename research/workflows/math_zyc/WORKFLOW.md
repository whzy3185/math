# 数学 zyc：研究推进与接管工作流

整理日期：2026-09-14。依据是用户关键对话的开场提示词、后续范围修正，以及仓库既有 `math-research-full-push` v5。提示词索引见 [PROMPT_SOURCES.md](PROMPT_SOURCES.md)，接管入口见 [HANDOFF.md](HANDOFF.md)。本文件整理工作方式，不认证历史数学结论。

## 1. 工作目标

从真实文献中的精确问题出发，完成可以独立审查的数学结果，持续尝试更强的结构定理，再形成符合目标期刊的完整论文。计算、Lean、仓库和写作都服务于这条证明链。每轮必须产生可检查的研究增量，不能以提纲、目录、计划或未编译源码替代结果。

两种入口：

- **新选题**：近期论文或明确研究缺口 → 原文及后续文献核验 → 候选命题与低成本反驳路线 → 选定主问题 → 新分支。
- **已有课题／Remark**：读取原文及假设 → 恢复仓库最强结论与真实证明源 → 查明被替代和撤回结果 → 继续当前最高优先级证明义务。

“一区”或某期刊是选题与成果强度目标，不是预先保证。数学目标改变时重新评估期刊。

## 2. 每轮先恢复状态

1. 确认本课题的分支、提交 SHA、论文目录和研究对象。
2. 读取最近提交、定理账本、证明依赖图、失败路线、最新文献核查、交接记录。
3. 跨分支追到真实证明与验证脚本。`main`、README、`FINAL`、`CURRENT`、`READY` 以及聊天中的“完成”只作导航，不能替代核查。
4. 对每条候选定理明确量词：指定构造还是所有构造、连续相位还是有限采样、固定参数还是统一参数、存在性还是分类／唯一性。
5. 若原研究者仍在推进，固定读取快照，在独立工作分支保存本轮工作；合入更新前比较新增提交和定理范围。

最少状态文件复用现有命名，避免另造重复账本：

| 文件 | 必须包含 |
|---|---|
| `README.md` 或研究状态 | 当前对象、最强可靠结论、入口和下一任务 |
| `THEOREM_LEDGER.md`／`CLAIM_LEDGER.md` | 陈述、假设、量词、证据级别、源文件及提交、替代关系 |
| `PROOF_DEPENDENCY_MAP.md`／`PROOF_GRAPH.md` | 引理依赖、外部定理、缺口、有限化与覆盖责任 |
| `LITERATURE_AUDIT.md` | 原始出处、最接近结论、最新进展、逐定理比较及核查日期 |
| `HANDOFF.md` | 本轮变化、已执行检查、失败路线、准确续接点 |

## 3. 优先级与循环

优先级依次为：正确性纠错 → 反例检查 → 新颖性冲突 → 主证明瓶颈 → 定理加强 → 所需形式化／验证 → 论文与模拟审稿 → 冻结打包。

每轮执行：恢复状态 → 选择一个具体数学问题 → 实际推导／检索／计算 → 对抗性审查 → 修复或加强 → 更新账本与证明源 → 提交可复核增量 → 继续。

有效增量包括：排除一条错误路线、找到反例、澄清文献重合、证明结构引理、关闭证明分支、建立精确有限化、完成独立验证、编译通过对应形式化定理、用更强数学解决一项审稿异议。整理文件可以作为交付步骤，但本身不算数学进展。

## 4. 证据等级

| 标签 | 含义 | 不能据此声称 |
|---|---|---|
| `Observed` | 数值、拟合或实验现象 | 一般成立、唯一、最优 |
| `Verified finite` | 指定有限范围内的严格精确验证 | 未计算范围成立；无限族已证明 |
| `Proved` | 完整解析论证，或解析有限化与严格穷尽证书组成的闭合证明链；必须标明后者为计算机辅助 | 独立同行审稿已通过；Lean 已编译 |
| `Published/Established` | 外部公开文献中的已知结果，已匹配实际假设 | 本项目的新贡献 |

原提示词使用 `Verified`；这里写为 `Verified finite` 以明确其范围。计算机辅助证明需要逐一证明：为什么归约有限、为何覆盖完整、如何准确判定、证书如何复核。搜索生成器与验证器尽量独立。保留参数、版本、命令、输出、散列以及失败样例。

Lean 状态另列：未启动／源码已写／构建失败／指定工具链编译通过／与论文陈述对齐。只有无 `sorry`、`admit`、占位与偷渡假设，并真实通过构建的对应陈述，才能称为形式化验证。关键结构归约未覆盖时，不得用外围算术模块的通过替代主定理。

## 5. 主动加强与反驳

长证明前先检查小规模、退化和边界情形、符号约定、等号、反向蕴含、删除假设与有限／无限量词。发现错误立即修正全部依赖处，并保留撤回理由。

证明完成后依次尝试：扩大适用范围、减少假设、优化常数、等号与极值配置、必要充分条件、完整分类、刚性、稳定性、统一结构机制。更强结论成立后重新核查文献，并围绕更强结论重写论文。强化方向被反例否定、已见于文献或成本明显不相称时，记录具体障碍。

## 6. 两篇 circulant 论文的范围隔离

| 项目 | 分支 | 初始任务的数学范围 |
|---|---|---|
| 周期谱与渐近 | `paper/circulant-periodic-gap-20260909` | 显式周期 signing、连续 Bloch/Floquet 谱、谱隙渐近与相位效应 |
| 有限全局极值 | `paper/circulant-finite-threshold-20260909` | 有限 `C_N(1,s)` 上 `m(N,s)=min_sigma rho(A_sigma)`；所有 signing 的极值、阈值分类与刚性 |

两篇最终各自证明闭合、可以独立投稿与送审；不以另一篇未发表定理作黑箱，不写 companion paper 式依赖。所需标准工具在本篇证明，或引用实际公开的外部文献。历史材料可启发思路，但不能替代本篇证明。

后续若周期课题加强为固定周期的全类分类，仍须记录“固定周期类”的精确定义；不能自动把结果升级成任意有限图上所有 signing 的全局最优性。相同的“period-8”还必须核对 jump、相位和边计数，不能混用 `s=2` 与 jump-4 模型。

## 7. 文献、写作与模拟审稿

文献工作围绕：原始问题 → 最接近的定理 → 最新边界 → 仍存缺口 → 本文贡献。核对后续版本、勘误、前后向引用及同作者续作。比较定义域、假设、结论、等号、范围与方法；不能仅凭旧论文的开放问题或摘要宣布新颖。

论文围绕最强稳定数学推进，以问题和未解决障碍自然引出下一条引理。保留完整英文稿、必要中文稿、LaTeX、参考文献和验证附件。数学正文与工程日志、投稿元数据分开；减少碎小标题、施工式路线图和防御性解释。数学不足要转成证明义务，不能仅改措辞。

每个重要版本：模拟目标期刊审稿 → 列出正确性／新颖性／完整性／黑箱问题 → 修复、补证或加强 → 重新编译并查看实际 PDF → 再审。模拟审稿不能写成真实审稿结论；干净构建也不代表交叉引用语义、页面和公式渲染正确。

冻结条件：没有已知正确性阻塞，关键依赖闭合，强化已尝试并说明停止理由，文献定位更新，正文／补充材料／形式化陈述一致，关键验证完成，PDF 已检查，准确续接点已保存。出现反例、文献撞车或实质定理升级应重新打开。

## 8. 简短用户指令如何执行

| 指令 | 实际动作 |
|---|---|
| 继续／推进 | 从当前分支恢复最高优先级未解决问题，实际执行一轮，不重复询问做什么 |
| 继续增强／升级定理 | 先反驳更强版本，再证明有价值的加强，更新文献定位 |
| 给最终定理 | 给出当前证据支持的最强完整陈述；列明计算机辅助、外部依赖与未闭合部分 |
| 推进 Lean | 形式化并编译最有价值的证明依赖，核对与论文的陈述一致性 |
| 仿照 JCTA 推进 | 核心贡献、完整分类、精确证书和审稿问题一起推进，不限于英文润色 |
| 看 PDF／给文件 | 真正编译、渲染检查，交付可下载文件与仓库位置 |

“继续”在当前会话中表示继续执行；若需要退出会话后定时运行，必须另行明确调度。不能把文字中的长期工作意图描述成已经在后台运行。

## 9. 每轮交付的最小报告

报告本轮具体数学变化及其意义、证据等级、所用分支与提交、执行过的检查、剩余缺口和下一个准确问题。每条“已完成”都能指到实际文件或验证结果。按用户既定范围推进与提交；合并主分支、实际投稿和对外沟通分别按当前授权处理。
